# Закрытый Telegram-бот для учёта оплаты зарубежных сервисов

Бот автоматизирует учёт: заявки друзей, расчёт суммы в рублях, приём оплаты, статусы, балансы, история, напоминания.
Саму оплату картой админ делает вручную. **Бот не хранит и не обрабатывает реквизиты банковских карт** — только метки вида «Visa ··4417».

> Статус: **этап 4 из 5** (+ подписки и напоминания, статистика, экспорт, бэкапы). См. `docs/CONTEXT_SNAPSHOT.md`.

## Стек
Node.js 20+, TypeScript (strict), pnpm, grammY, PostgreSQL + Prisma, Fastify, Zod, pino, Vitest, Docker.

## Быстрый старт (локально, long polling)
```bash
pnpm install
cp .env.example .env            # заполни BOT_TOKEN, ADMIN_TELEGRAM_ID, ENCRYPTION_KEY, POSTGRES_PASSWORD
openssl rand -base64 32         # → ENCRYPTION_KEY
docker compose up -d db         # только база
pnpm prisma migrate deploy
pnpm dev
```
Без Docker подойдёт любой PostgreSQL 14+: поправь `DATABASE_URL`.

## Запуск на сервере (VPS)
```bash
git clone <repo> && cd <repo>
cp .env.example .env            # заполнить; BOT_MODE=polling не требует домена и HTTPS
docker compose up -d --build    # db + app + backup
docker compose logs -f app
```
Миграции применяются автоматически при старте контейнера `app`. Бэкапы: `./backups` (ежедневно, хранится 14 дней).
Восстановление: `gunzip -c backups/daily/bot-latest.sql.gz | docker compose exec -T db psql -U bot -d bot` (в пустую базу).
Проверить, что бэкап реально восстанавливается (дамп → временная БД → сравнение числа строк по всем таблицам):
`DATABASE_URL=postgresql://bot:<пароль>@localhost:5432/bot ./scripts/verify-backup.sh` (нужен `postgresql-client`).
⚠️ Бэкап БД содержит коды подарочных карт только в зашифрованном виде — **храни `ENCRYPTION_KEY` отдельно от бэкапов**. Без ключа зашифрованные коды не прочитать.

**Webhook (по желанию):** нужен домен с A-записью на сервер. В `.env`: `BOT_MODE=webhook`,
`WEBHOOK_URL=https://<домен>/webhook`, `WEBHOOK_SECRET=<16+ символов>`, `DOMAIN=<домен>`; запуск:
`docker compose --profile webhook up -d --build` (Caddy сам получит сертификат).

## Переменные окружения
| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `ADMIN_TELEGRAM_ID` | твой Telegram ID — единственный админ |
| `ADMIN_CHAT_ID` | куда слать служебные уведомления (по умолчанию = админ) |
| `BOT_MODE` | `polling` (по умолчанию) или `webhook` |
| `WEBHOOK_URL`, `WEBHOOK_SECRET` | только для webhook; секрет проверяется по `X-Telegram-Bot-Api-Secret-Token` |
| `HTTP_HOST`, `HTTP_PORT` | Fastify (`/health`, `/webhook`) |
| `DATABASE_URL` | строка подключения PostgreSQL |
| `POSTGRES_USER/PASSWORD/DB` | для docker-compose |
| `ENCRYPTION_KEY` | 32 байта base64, AES-256-GCM для кодов подарочных карт. **Сохрани копию отдельно от бэкапов БД** |
| `TIMEZONE` | часовой пояс напоминаний (`Europe/Moscow`) |
| `LOG_LEVEL` | `info` по умолчанию |

## Как создать первого клиента
1. Напиши боту `/start` со своего аккаунта (ID из `ADMIN_TELEGRAM_ID`) — получишь меню админа.
2. `/invite Вася` — бот пришлёт одноразовую ссылку `https://t.me/<bot>?start=<код>` (действует 72 ч).
3. Друг открывает ссылку и жмёт Start — регистрируется, тебе приходит уведомление.
4. Все остальные получают вежливый отказ.

## Как работает заявка
1. Клиент: «➕ Новая заявка» → тип (ссылка / подарочная карта / пополнение / другое) → ссылка → сервис → сумма и валюта → разовая или подписка → комментарий → «Отправить».
2. Админ получает карточку: тип, сервис, сумма, домен (✅ доверенный / ⚠️ НЕИЗВЕСТНЫЙ ДОМЕН), возраст заявки. Кнопка «🧮 Рассчитать».
3. Клиент видит итог в рублях → «Подтвердить и оплатить» → выбирает способ перевода → переводит → «Я оплатил» (+чек).
4. Админ: «✅ Оплата получена» (или «🚫 Оплата не найдена») → в статусе «В работе» появляется кнопка «🔗 Открыть ссылку».
5. Админ платит картой вручную → «✅ Выполнено» → карта → фактическое списание → курс → (скриншот) → подтверждение.
   Бот считает разницу и записывает её в баланс клиента. Для подарочных карт код вводится при «Выполнено» и уходит клиенту; в БД хранится зашифрованным.

## Подписки и напоминания
- При «Выполнено» для подписки ставится дата следующего списания (месяц / год / свой период).
- За `subscriptionRemindDays` дней (по умолчанию 3) после `reminderHour` (10:00 по `TIMEZONE`) клиент и админ получают напоминание. У клиента кнопки **«🔁 Продлить»** (создаётся новая заявка с теми же данными; клиент присылает свежую ссылку и заново выбирает режим оплаты) и **«Не продлевать»** (напоминания прекращаются).
- Одно напоминание на каждое списание; для подписки с уже оформленным продлением и для заблокированных клиентов напоминаний нет. `/subs` — список подписок по ближайшему списанию.
- Коды подарочных карт стираются из БД через `giftCodeRetentionDays` (по умолчанию 7) дней после «Выполнено» — проверка каждые 5 минут.
- Напоминания о долге — раз в `debtReminderDays` дней.

## Статистика и экспорт
`/stats [период]` — созданные и выполненные заявки, **оборот** (выставлено клиентам), **фактические расходы**, **валовая прибыль** (оборот − расходы: наценка + комиссия + курсовая разница), пополнения и погашения, разбивка по клиентам / сервисам / картам.
`/export [период]` — два CSV-файла: заявки и операции баланса. В заявках только домен ссылки (не вся ссылка), коды подарочных карт не экспортируются, ячейки со свободным текстом защищены от формул Excel (`=`, `+`, `-`, `@`). Файлы в UTF-8 с BOM, разделитель запятая, суммы в рублях через точку (в Excel: «Данные → Из текста/CSV»; в Google Sheets открывается сразу).
Период: `month` (по умолчанию), `prev`, `week`, `today`, `all`, `2026-09`, `2026-09-15`, `2026-09-01 2026-09-30` — в часовом поясе `TIMEZONE`. Для заявок период считается по дате создания, в статистике — по дате выполнения.

## Режимы оплаты клиента
В диалоге заявки последним шагом клиент выбирает режим (шаг пропускается, если доступен только перевод):
| Режим | Как работает |
|---|---|
| 💳 **Перевод (PREPAY)** | Клиент переводит итог до того, как ты платишь. По умолчанию. |
| 💰 **С баланса (BALANCE)** | Доступен при положительном балансе. При подтверждении расчёта сумма **резервируется**. Если баланса хватает — заявка сразу «В работе». Если нет — резервируется весь баланс, а разницу клиент **доплачивает переводом**. Отмена, истечение или отклонение возвращают резерв на баланс. |
| ⏳ **Оплата позже (PAY_LATER)** | Только если ты включил: `/paylater <id> on <лимит ₽>`. Лимит проверяется при подтверждении (долг + открытые заявки «в долг» + новая ≤ лимита), заявка сразу «В работе». Долг (`DEBT_OPEN`) возникает при «Выполнено». Напоминания раз в `debtReminderDays` дней после `reminderHour`. |

Баланс клиента — **только сумма проводок** `LedgerEntry`; отрицательный баланс = долг. Проверка баланса и лимита идёт под блокировкой строки клиента, поэтому параллельные заявки не потратят одни и те же деньги.
Пополнение (`➕ Пополнить баланс`): сумма → способ → чек → ты подтверждаешь кнопкой. Если есть долг, сначала гасится он (`DEBT_REPAY`), остаток идёт на баланс (`TOPUP`).

**Расчёт:** `итог = сумма × курс × (1 + запас) × (1 + наценка) + фикс`, округление вверх до целых рублей. Курс — ЦБ РФ (кеш 1 час) или ручной (`/rate`). Параметры и курс фиксируются в заявке на момент расчёта.

**Разница по факту:** `оценка себестоимости (сумма × курс × (1 + запас)) − фактическое списание в ₽`.
Положительная — переплата клиента (зачисляется на баланс), отрицательная — доплата (списывается). Наценка и фикс. комиссия в разницу не входят — это доход админа.

## Команды
**Клиент:** кнопки меню «➕ Новая заявка», «📋 Мои заявки», «💰 Мой баланс» (баланс/долг и история), «➕ Пополнить баланс»; `/cancel` — отменить диалог.

**Админ:**
| Команда | Что делает |
|---|---|
| `/invite [заметка]`, `/invites` | создать инвайт / список активных |
| `/clients`, `/block <id>`, `/unblock <id>` | клиенты (с балансами), блокировка |
| `/client <id>` | карточка клиента: статус, баланс/долг, последние операции |
| `/debts` | кто мне должен и у кого переплата/остаток |
| `/adjust <id> <±сумма ₽> [комментарий]` | ручная корректировка баланса (проводка `MANUAL_ADJUST`, клиент получает уведомление) |
| `/paylater <id> on [лимит ₽] \| off` | включить/выключить «оплату позже» и задать лимит долга |
| `/settings [ключ значение]` | запас на конвертацию, наценка, фикс. комиссия, TTL расчёта и др. |
| `/domains`, `/domain_add`, `/domain_del` | доверенные платёжные домены |
| `/orders` | открытые заявки |
| `/stats [период]`, `/export [период]`, `/subs` | статистика, CSV-выгрузка, список подписок |
| `/rate`, `/rate USD 95,5`, `/rate USD clear` | курсы: показать / задать вручную / вернуть ЦБ |
| `/cards`, `/card_add Visa ··4417 USD`, `/card_toggle <id>` | твои карты: только метка и валюта |
| `/methods`, `/method_add Название \| Инструкции \| да`, `/method_edit <id> \| Текст`, `/method_receipt <id> да\|нет`, `/method_toggle <id>` | способы перевода от клиентов |

В инструкциях способов оплаты номера банковских карт запрещены (бот их не принимает) — указывай телефон СБП, банк и имя получателя.

## Первичная настройка после запуска
```
/card_add Visa ··4417 USD
/method_edit 1 | СБП на +7 900 000-00-00, Т-Банк, получатель Иван И.
/rate USD 95        # необязательно: иначе берётся курс ЦБ
/settings markupBp 5
```

## Архитектура
`src/bot` (хендлеры, middleware, клавиатуры) · `src/domain` (чистая логика: деньги, настройки, домены) ·
`src/services` (БД-сервисы, шифрование, rate limit) · `src/db` · `src/http` · `src/texts` (все тексты).

Безопасность: роль проверяется middleware на каждое обновление (+ `requireAdmin` в админских композерах);
инвайт гасится атомарно в транзакции; `LedgerEntry` и `OrderEvent` защищены от UPDATE/DELETE триггером БД;
деньги — `BigInt` в минимальных единицах; логи без текстов сообщений, ссылок и кодов; работа только в личных чатах.
